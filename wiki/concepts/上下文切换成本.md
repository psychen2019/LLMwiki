# 上下文切换成本 (Context Switching Cost)

## 定义

从一项高认知负荷任务切换到无关事务，再切回时必须重新经历的"预加载"代价。

## 类比

把大脑想成计算机：

```
处理高负荷任务 = 运行大型游戏（需渲染复杂 3D 场景）
工作记忆       = 内存 + 显存
长期记忆       = 硬盘
预加载         = 把长期记忆的概念、逻辑、变量搬运到工作记忆
```

## 切换过程

1. **预加载完成**：工作记忆已被复杂上下文占满，效率极高，进入[[心流]]
2. **被打断**（老板问"中午吃啥"）：相当于拔掉内存电源
3. **加载低级模型**：为回复问题必须在清空的内存中加载"午饭菜单"
4. **回归原任务**：必须重新经历痛苦的预加载过程，把复杂逻辑一砖一瓦地搭起来
5. **净损失**：平白无故多花一笔加载时间，还可能出错

## 主要后果

- 程序员最恨被打断
- 高水平工作**不能多任务处理**
- 不是所有任务都需要大段时间——只有高负荷任务必须关起门来单干
- 事务型、流程型任务可脚本化、批处理，无需专注

## 与本课其他概念的关系

- **[[主动高认知负荷]]**：高负荷任务一旦进入，切换成本极高
- **[[心流]]**：心流状态下切换成本达到峰值——任何打扰都摧毁心流
- **[[注意力]]**：切换成本是注意力无法并行的物理基础
- **[[认知负荷理论]]**：高内在负荷+高增益负荷的任务切换成本最大

## 实操建议

- 低负荷任务（打扫、做饭、刷碗）：可多任务并行（聊天+刷手机+听音频）
- 高负荷任务（建模型、探索性任务）：必须大段时间单干
- 关键筛选标准：**是否需要同时托举很多相互依赖的变量**

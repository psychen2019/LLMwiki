# Research: 贪心算法 vs 动态规划的边界：何时贪心足够，何时必须用 DP？

# 贪心算法 vs 动态规划的边界：何时贪心足够，何时必须用 DP？

## 概述

贪心算法（Greedy Algorithm）与动态规划（Dynamic Programming, DP）都是求解最优化问题的经典算法范式，二者都依赖"最优子结构"（Optimal Substructure）这一性质——即原问题的最优解可由子问题的最优解组合而成。然而，两者在"如何使用子问题的解"上存在根本分歧，由此划出了各自适用的边界。理解这条边界，是算法选型的核心问题 [1][2]。

## 共同基础：最优子结构

两类算法都要求问题具备**最优子结构**：一个问题的最优解包含其子问题的最优解。这也是它们区别于[[分而治之]]（如归并排序）的关键前提——后者只要求子问题相互独立，不需要"最优性"在子问题间传递 [4]。

## 核心差异

### 1. 求解路径：自顶向下 vs 自底向上

- **贪心算法**：采用"自顶向下"的路径，但**不等待子问题求解完毕**。每一步基于当前状态选择一个子问题去求解，未被选中的分支被直接放弃 [1][4]。这种"剪枝"是贪心区别于 DP 的最显著特征。
- **动态规划**：无论是自底向上（表格填充）还是自顶向下（备忘录/记忆化搜索），都会**枚举所有相关子问题**，从边界出发逐步推导出目标问题的解 [1][2]。

### 2. 选择策略：局部最优 vs 全局累积

- **贪心**：在每一步采取"当前最佳"（best so far），希望通过这种局部最优的累计获得全局最优。它**不考虑全局最优解的结构**，正确性必须依赖单独的归纳证明 [2]。
- **动态规划**：通过状态转移方程（State Transition Equation）系统地汇集所有子问题的解，再组合出当前问题的解。它要求明确定义**状态**、**状态转移方程**、**初始化条件**与**边界条件** [2][3]。

### 3. 时间复杂度与子问题覆盖

- 动态规划通过存储子问题结果（备忘录或 DP 表）将递归的指数级时间降到多项式级，但代价是**覆盖全部子问题** [4]。
- 贪心算法只走一条路径，时间复杂度通常更低，但**仅当"局部最优可推导全局最优"时才正确**。

### 4. 正确性证明路径

- 贪心的正确性证明通常是**归纳法**（或交换论证）：假设前 k 步贪心选择构成某最优解的前缀，证明第 k+1 步的贪心选择也能并入某最优解 [1]。
- 动态规划的正确性证明则是**递推不变式**（induction on subproblem size）：边界正确，转移正确，则全局正确 [3][5]。

## 何时贪心足够，何时必须用 DP？

综合各来源，可以提炼出以下判别启发式 [1][2][5]：

| 判别条件 | 贪心可行 | 必须用 DP |
| --- | --- | --- |
| 是否需要考虑多个子问题的组合？ | 否，只需一个"当下最优" | 是，需枚举所有子问题 |
| 局部最优是否可推导全局最优？ | 是（需数学证明） | 否，局部最优会误导 |
| 问题是否具有"拟阵"或"拟阵类"结构？ | 是 | 否 |
| 是否存在"重叠子问题"且需复用计算？ | 不需要复用 | 强需要 |
| 状态转移是否涉及"放弃当前最优以换取后续更大收益"？ | 否 | 是 |

**典型贪心场景**：活动选择（区间调度）、最小生成树（Kruskal/Prim）、单源最短路（Dijkstra，需非负权）、哈夫曼编码等。这些问题的共同特征是**贪心选择性质**（Greedy Choice Property）成立 [1][2]。

**典型 DP 场景**：0-1 背包、最长公共子序列、最短路径含负权边（Floyd-Warshall）、编辑距离、区间 DP 等。这些问题中"眼前的小选择"会影响后续可达状态，**局部最优不蕴含全局最优** [2][3]。

## 常见的辨析误区

- **"贪心比 DP 快"是错误印象**：贪心快是因为它放弃了大量子问题分支；若贪心选择不成立，再"快"的贪心也会给出错误答案 [1]。
- **"DP 是贪心的超集"也是一种过度简化**：DP 的状态转移表并不等于"每步都贪心"，二者是两种不同的**解题哲学**——前者是**穷举 + 查表**，后者是**决断 + 赌正确** [4][5]。
- **"自顶向下 vs 自底向上"只是实现层面区别**：DP 既可自顶向下（备忘录）也可自底向上（表格），但贪心只有自顶向下，因为不存在"先填满所有子问题"这一步 [1][4]。

## 矛盾与空白

当前可收集到的来源在以下几点上存在**表述不一**：

1. **关于 DP 是否必须考虑所有子问题**：来源 [1] 明确说 DP"考虑所有子问题"，而来源 [4] 强调 DP 的核心是"存储子问题结果以避免重复计算"。前者强调枚举范围，后者强调计算复用——两者并不矛盾，但在"是否可能剪枝"上留下了模糊空间。
2. **关于"自顶向下/自底向上"的归属**：来源 [4] 将分而治之和贪心都归为"自上而下"，将 DP 归为"自下而上"；但来源 [1] 指出贪心"不等待子问题求解完毕"，因此严格说贪心并非真正自顶向下的完整递归。这一区分在文献中并非总被强调。
3. **量化判别标准的缺失**：现有来源都给出**定性判别**（如"是否具备贪心选择性质"），但对"在算法设计阶段如何快速判断"的可操作清单覆盖较少。这是一个明显的研究空白。

## 进一步研究方向

为了加深对二者边界的理解，建议补充以下来源：

- [[Cormen]] 等《算法导论）第 16 章「贪心算法」与第 15 章「动态规划」——经典教材中关于"拟阵"与"拟阵贪心定理"的讨论，是判断贪心可行性的形式化工具。
- Kleinberg & Tardos《Algorithm Design》第 6 章——对"拟阵"与"贪心选择性质"的形式化证明，以及对区间调度等案例的交换论证。
- 关于"贪心失败需 DP"的具体反例集合（如带负权的最短路、退化的背包变种），可作为教学素材。
- 关于"何时剪枝 + DP"（即 DP 中加入贪心剪枝/启发式函数）的进阶讨论，对应 A\*、IDA\* 等启发式搜索算法。
